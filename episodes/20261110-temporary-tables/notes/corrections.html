Corrections (checked against the Postgres source after recording)
  • [00:13:58] Two temp tables and an index are not "three records in, three out". Each temp table adds at least 13 catalog rows (pg_class, pg_type, pg_attribute, pg_depend), about 31 if it has a text column, and the index adds more. So 10M queries a day means at least 600 million catalog row changes, not 60M.
  • [00:15:47] sinval means shared invalidation (of the catalog and relation caches), not "snapshot invalidation".
  • [00:18:49] LWLock:LockManager: up to Postgres 17 a session has 16 fast-path lock slots; Postgres 18 has 64 by default and scales them with max_locks_per_transaction. But temp-table DDL takes AccessExclusiveLock, which never uses the fast path, so raising the setting does not make this wait go away (the brief measured 6.6 to 12.7% LockManager with it set to 1024).
  • [00:25:09] The invalidation queue is a circular buffer of 4,096 messages, but writers never wait for readers. When it is half full (2,048 messages), the session that is furthest behind gets a catch-up signal, and it passes the signal on, one session at a time. When it is full, sessions that have not read are reset and must rebuild all their caches. Writers wait on SInvalWriteLock because there is one such lock for the whole cluster, and both a write (which flags every session) and a queue cleanup (which scans every session) hold it.
  • [00:27:26] ON COMMIT DELETE ROWS does not make dead tuples: at commit it truncates the table and its indexes. And ON COMMIT DROP is not slow mostly because of more messages: without idle sessions the cost is catalog changes and file create and unlink; sinval is under 1%.
Clarifications
  • [00:04:02] Temp table data is invisible to other sessions, but the definition and statistics are visible (pg_class, pg_stat_all_tables).
  • [00:05:32] The docs glossary defines bloat, and the definition includes dead row versions.
  • [00:14:56] Wraparound: load is not the condition. Autovacuum never freezes temp tables, so any long-lived temp table holds back datfrozenxid.
  • [00:17:05] "Catalog is global": the catalog is per database and visible to all its sessions; the invalidation queue is one per cluster.
  • [00:17:48] Global temporary tables: the old patch stalled in 2022, but a new one by Dean Rasheed is in review for Postgres 20.
  • [00:18:40] 16 vCPU (8 cores with SMT), not 16 cores.
  • [00:19:39] "CPU is low" refers to the share of active-session samples; the host CPU was busy, and in another run (1,000 idle sessions, 100 DDL tx/s) idle sessions spent 1.4 to 2 vCPU on catch-up.
  • [00:23:38] Andres Freund's work on many idle connections is in Postgres 14.
  • [00:24:06] Samplers that see only active sessions (like Performance Insights, now CloudWatch Database Insights) miss the idle sessions that wait during catch-up.
  • [00:26:50] The numbers: 3,931 tx/s (temp table per transaction), 17,741 tx/s (reused temp table), 88,531 tx/s (CTE). So the CTE is about 5x the reused temp table [00:28:15].
  • [00:30:27] select t1 from t1 returns the table's composite row type t1, and the array is t1[].
  • [00:35:20] What is emitted is invalidation messages; SInvalWrite is the lock writers wait on.
  • [00:35:43] The sinval design and the 4,096 constant are from Tom Lane's 2008 rewrite; it was changed later too (2011, 2015, 2024, 2026).
  • [00:37:55] PgBouncer: DISCARD ALL (server_reset_query) runs when a client disconnects in session mode; in transaction mode no reset query runs by default.
